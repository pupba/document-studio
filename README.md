# PRESTIQUE Document Studio

프레스티크 주식회사용 **로컬 우선 회사 문서 웹 앱**입니다. 견적서뿐 아니라 공문, 발주서, 품의서, 거래명세서, 지출결의서, 회의록, 업무보고서, 업무협조전, 자유양식을 작성·저장·발행하고 A4 PDF로 출력할 수 있습니다.

> **현황:** 정적 웹 앱 실행 가능. GitHub 저장소에는 자동 반영하지 않았으며, 제공된 ZIP을 직접 실행하거나 새 저장소에 배포하세요.

## 포함 기능

- 10종 템플릿: 공문 / 견적서 / 발주서 / 거래명세서 / 품의서 / 지출결의서 / 회의록 / 업무보고서 / 업무협조전 / 자유양식
- 필드 편집, 본문 단락 추가·삭제, 거래 품목 추가·삭제, 품목 이미지 등록(PNG/JPG/WebP · 최대 8MB), 내용 실시간 A4 미리보기
- 문서번호 `PTQ-[종류]-[연도]-[4자리]` 로컬 자동 생성 / 수정 가능
- 작성일, 수신처, 제목, 담당부서, 작성자, 본문, 첨부서류, 비고
- 원화 정수 기반 부가세 별도·포함·미반영 자동 계산(기존 견적서 프로젝트 로직 계승)
- 공식 OLIAVÉ 딥그린·골드·화이트 **원본 로고 3종** 내장 (회사 기본 로고 설정, 문서별 변경)
- 회사 정보, 대표자 성명, 등록번호, 주소, 연락처, 은행정보 및 날인 이미지 설정
- 상태: 초안 → 발행 완료. 발행본은 UI에서 편집 잠금, 개정본 생성(원본 보존)
- IndexedDB 자동 저장, 문서 검색·분류, 복사, 삭제, 전체 JSON 백업·복원
- A4 인쇄 / Chrome·Edge `인쇄 > PDF로 저장`
- 모바일 편집 및 미리보기 전환
- GitHub Pages 정적 배포 워크플로 (서버/계정 불필요)

## 실행

Node.js 22 이상에서:

```bash
npm run dev
# http://localhost:4173
```

테스트와 배포용 빌드:

```bash
npm test
npm run build
npm run check
```

`dist/`을 정적 호스팅 서버에 올리면 됩니다. GitHub Actions는 `.github/workflows/deploy.yml`을 사용합니다. GitHub 저장소의 Settings > Pages > Build and deployment > Source를 **GitHub Actions**로 설정하세요.

## 사용 순서

1. `회사 기본정보`에서 대표이사·사업자번호·주소·연락처를 입력합니다. 확인되지 않은 회사 데이터는 기본으로 비워 두었습니다.
2. `새 문서 만들기`에서 서식을 고릅니다.
3. 중앙 편집기의 각 필드를 작성하면 우측 A4 미리보기에 즉시 반영됩니다.
4. 필요하면 `발행 확정`으로 초안을 잠급니다. 발행 전 검증 항목을 충족해야 합니다.
5. `PDF 저장`을 눌러 브라우저 인쇄 화면에서 A4, 배율 100%, 배경 그래픽 사용 옵션으로 저장하세요.
6. 왼쪽 `데이터 백업 / 복원`에서 전체 JSON 파일을 내려받습니다.

## 공문 참조 서식

사용자가 제공한 `간접비10%공문예시(참고용).pdf` 1페이지의 공문 필드(문서번호, 시행일, 수신, 발신, 제목, 번호별 본문, 법인명과 대표이사, 날인, 연락처)를 참고했습니다. 원본의 연락처·개인정보·회사 상호는 복제하지 않았습니다. 공문 예시의 실제 내용은 템플릿에 삽입하지 않았습니다.

## 원본 브랜드 자산

`assets/oliave_logo_deep_green.png`, `assets/oliave_logo_gold.png`, `assets/oliave_logo_white.png`는 사용자가 이전에 제공한 `Oliave_IR_Asset_Library.html`에 포함된 공식 PNG 원본에서 그대로 추출했습니다. 변형·색상 변경·리터칭 없이 사용합니다. 소스북 BI 지침에 따라 어두운 배경에는 화이트, 밝은 배경에는 딥그린을 권장합니다.

## 데이터·보안·한계

- 데이터는 해당 브라우저/도메인의 IndexedDB에 **로컬 저장**합니다. 서버, API, 분석 SDK를 사용하지 않습니다. 외부 폰트/CDN을 사용하지 않습니다. 시스템에 설치된 한글 폰트를 사용합니다.
- 브라우저 삭제, 기기 변경, 도메인 변경 시 데이터는 이전되지 않습니다. JSON 백업을 주기적으로 만드세요.
- 로컬 발행 잠금은 브라우저 UI 수준입니다. 파일과 저장소가 변경 불가하다는 증명, 법적 효력 있는 전자결재/전자서명, 권한통제, 감사 로그, 블록체인·해시 기반 위변조 방지 기능이 **아닙니다**.
- 문서번호는 해당 브라우저 보관 문서 범위에서 생성되므로 타 기기와의 전사적 중복 방지를 보장하지 않습니다.
- 견적서는 세금계산서가 아니며 부가세 미반영 모드는 면세나 영세율 판단이 아닙니다. 실제 발행 전 세무 검토가 필요합니다.
- 날인 이미지는 이미지 표시이며 인증된 전자서명이 아닙니다.
- PDF는 네이티브 인쇄 기반입니다. 브라우저에 따라 줄바꿈이 다를 수 있습니다. 장문 또는 다중 페이지 문서는 최종 PDF 출력 결과를 확인하세요.
- DOCX/HWP 다운로드, 다중 사용자 동기화, 클라우드 승인 워크플로, 중앙 문서 번호 발급은 1차 구현 범위에서 제외했습니다.

## 기존 견적서 생성기와 관계

기존 소스: https://github.com/pupba/quotation-generator (MIT, 2026). `src/model.js`의 VAT 계산 규칙과 로컬 우선/정적 배포 방식을 참조했습니다. 기존 견적서 프로젝트는 변경하지 않았습니다. 신규 앱은 별개 프로젝트이며 거래 문서와 회사 공식 서식 체계로 확장된 버전입니다.
